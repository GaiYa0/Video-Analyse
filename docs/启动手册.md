## 0. 先搞清：谁负责什么

| 组件 | 干什么 | 默认端口 | 进程特征 |
| --- | --- | --- | --- |

## 1. 一键启动（推荐：前后端 + WVP）

在 **Windows PowerShell**，仓库根目录：


| 1 | `start_easysva.ps1` | MariaDB、Redis、Nginx（前端）、`backend.jar`、ZLM、`Analyzer` |

### 1.0 常用开关


### 2.5 国标 SIP（WVP）

完整原理与预览/布控/真机见 **[国标功能使用说明书.md](./国标功能使用说明书.md)**。  
**日常请优先用 §1 的 `start_demo.ps1`**（已含 WVP）。下面是只起 / 重装 WVP 时用。

**首次**（只需做一次）：

```bash
cd /mnt/e/video-analysis/Video-Analyse-main
bash scripts/setup_wvp.sh      # 建库 wvp、写 easysva 配置
bash scripts/build_wvp.sh      # JDK 21 编译 jar
# 前端静态页（管理页空白时）：
bash scripts/serve_wvp_ui.sh   # 编译 web 并挂到 /opt/SVA/wvp/static 后重启
```

**日常只启动 / 重启 WVP**（业务栈已在跑时）：

```bash
bash scripts/start_wvp.sh
```

| 指令 | 启动内容 |
| --- | --- |
| `setup_wvp.sh` | MariaDB 库 `wvp` + 配置，不长期占端口 |
| `build_wvp.sh` | 编译 `/opt/wvp-GB28181-pro/target/wvp-pro-*.jar` |
| `start_wvp.sh` | WVP：Web **18080**、SIP **5060**；`on_publish` 指向 WVP（stream_replace），清空 `on_play`，关闭 push-authority |
| `serve_wvp_ui.sh` | 补管理前端静态资源并重启 WVP |

管理页：`http://127.0.0.1:18080/`  
演示机账号：`admin` / `SvaDemo@2026`  
SIP 只绑局域网 IP（如 `10.21.235.102:5060`），模拟器必须往这个 IP 注册，不要用 `127.0.0.1:5060`。  
业务网页同步国标：设备管理 → **同步国标设备**。

无真机时走 **真 SIP 注册 + 点播出画面**（不要用 `seed_wvp_device.sh` 冒充在线）：

```powershell
wsl -d Ubuntu-22.04 -u root -- bash /mnt/e/video-analysis/Video-Analyse-main/scripts/start_gb_sim.sh
# 或：.\scripts\start_demo.ps1 -WithGbSim
```

| 指令 | 启动内容 |
| --- | --- |
| `start_gb_sim.sh` | 模拟 IPC：REGISTER/保活/目录 → 自动点播 → ZLM `app=rtp`。默认睡岗片 `docs/fixtures/monisleep.mp4`；`VIDEO=` 可换成其他 mp4。竖屏会 pad 成 1280×720 |
| `prepare_gb_video.sh` | 可选：先把片源转成横屏 H.264 再给 `VIDEO=` |
| `rebuild_analyzer.sh` | 改过 `server/Analyzer` 后 GPU 编译并重启 `/opt/SVA/server/Analyzer` |

脚本会保持 `gb28181_sim.py` 运行；预览地址以脚本打印的 `rtp/<device>_<channel>.live.flv` 为准。`seed_wvp_device.sh` 只改数据库，**不会** REGISTER，点播无画面。本机模拟器会把 WVP 设备 `sdp_ip` 写成 `127.0.0.1`（避免局域网 DHCP 换 IP 后 INVITE 发到旧地址）；真机仍用当前局域网 IP。`start_wvp.sh` 会把 WVP `media.stream-ip` 写成 `127.0.0.1`，避免本机播放器走局域网 IP 被 Clash 拦。

水杯模拟器长推时约每分钟可能闪断几秒（前端会自愈）；接真机后无此限制。预览若仍像「只有一帧」，浏览器 **Ctrl+Shift+R** 强刷。无人观看约 **60s** 后 ZLM 会关掉无人流（`streamNoneReaderDelayMS`），WVP/业务再点播放会重新 INVITE——不要一直干等转圈。

### 2.6 怎么看 WVP 点播（出画面）

完整步骤见 [国标功能使用说明书.md](./国标功能使用说明书.md) §5。下面是对照。

先保证：easySVA 已起、WVP 已起、**刚跑过或正在跑** `start_gb_sim.sh`（模拟器进程不能关）。Clash/VPN 开着时只用 **127.0.0.1**，不要用局域网 IP。

**方法 A：WVP 管理页（排障）**

1. 浏览器打开 [http://127.0.0.1:18080/](http://127.0.0.1:18080/)  
2. 登录：`admin` / `SvaDemo@2026`  
3. 左侧 **设备接入 → 国标设备**  
4. 找到 `34020000001320000001`，状态应为 **在线**  
5. 点该行 **通道**  
6. 通道 `demo-ipc` 上点 **播放**，弹出「视频播放」窗口，应看到模拟器正在推的画面（默认 `monisleep.mp4`；若用了 `VIDEO=` 则是该文件）

`start_gb_sim.sh` 结束时已经自动点播过一次；你再点「播放」是再拉一次流，可以。

**方法 B：浏览器 / 播放器直接打开 FLV**

脚本成功时打印的地址（stream 是 **设备ID_通道ID**）。业务页请走 Nginx **HTTP-FLV**，不要用 `ws://…:8080`（Windows `8080→80` 经常升不了 WebSocket），也不要让业务播放器直连 9992：

```
http://127.0.0.1:8080/rtp/34020000001320000001_34020000001320000001.live.flv
```

VLC / 确认媒体层可用 ZLM 直连：

```
http://127.0.0.1:9992/rtp/34020000001320000001_34020000001320000001.live.flv
```

- 浏览器地址栏直接打开上面的 `:8080` HTTP-FLV 应开始下载/下发 FLV（不是 WebSocket 握手失败）  
- Chrome 地址栏往往 **不会** 自己出画面，请用方法 A（WVP Jessibuca）或方法 C（业务页 flv.js）  
- WVP 用 `:9992` + Jessibuca；业务页用 `:8080` + flv.js，不要对打  

**方法 C：业务网页**（看的是同步进 easySVA 的国标设备，不是 WVP 自己的播放器）

1. [http://localhost:8080/](http://localhost:8080/) 登录 `admin` / `admin123`  
2. 设备管理里认名字 **demo-ipc**（国标编码 `34020000001320000001`），点 **预览视频**（不要只点「启动监控」——那只改状态，不出画面）  
3. 不要对半程测试/SSRC 残留行点同步；「同步国标设备」现在只会收 WVP 已注册通道，不再把 `gbcam001`、8 位十六进制 SSRC 建成新设备  
4. 给 B/C 看时：`bash scripts/rewrite_play_url_for_lan.sh <当前LAN>`，写成 `http://<LAN>:8080/rtp/...`。他们打开 `http://<LAN>:8080/` 即可。A 本机 Clash 下仍用 `localhost:8080`，必要时把 `play_url` 再改回 `127.0.0.1` 或关 Clash。

### 2.7 接入真正的国标 IPC（替换水杯）

参数表与步骤全文见 [国标功能使用说明书.md](./国标功能使用说明书.md) §8。睡岗演示画面来自 `start_gb_sim.sh`（默认 `monisleep.mp4`），不是摄像头。真机与模拟器不要同时用同一个国标编码。

1. **停模拟器**（编码不同可并存，建议先停以免搅在一起）：  
   `wsl -d Ubuntu-22.04 -u root -- bash -lc "pkill -f gb28181_sim.py || true"`
2. 演示机已起：`start_easysva.ps1` + `start_wvp.sh`。Clash 可关，或至少别让它拦局域网。
3. Windows 防火墙放行 **UDP/TCP 5060**，以及 **UDP 30000–35000**（RTP 媒体）。
4. 摄像头与演示机同一局域网，能 ping 通演示机当前 IP（DHCP 会变；现网示例 `10.21.235.102`。变了要改 WVP `sip.ip` 和摄像机里的 SIP 服务器地址）。
5. 在摄像机「国标 / GB28181」里填：

| 摄像机项 | 填这个 |
| --- | --- |
| SIP 服务器地址 | 演示机当前局域网 IP（**不要** `127.0.0.1`） |
| SIP 端口 | `5060`（UDP，部分机型可 TCP） |
| SIP 服务器 ID / 平台 ID | `34020000002000000001` |
| SIP 域 | `3402000000` |
| 设备国标编码 | 机身 20 位编码（**不要**再用模拟器的 `34020000001320000001`） |
| 注册密码 | `12345678` |
| 心跳 | 建议 ≤ 60 秒 |

6. 保存后等几十秒。WVP [http://127.0.0.1:18080/](http://127.0.0.1:18080/) → **设备接入 → 国标设备**：新编码 **在线** → **通道 → 播放**，应是现场画面。
7. 若注册成功但点播黑屏：WVP 里把该设备传输模式改成 **UDP**（不要 TCP-PASSIVE），再点播放。
8. 业务页「同步国标设备」，出现该通道后可预览。睡岗/YOLO 布控：国标 Analyzer 拉 `rtsp://…/rtp/<设备_通道>`；直连 RTSP 仍拉 `live/<ape_id>`。ZLM 还没有该 rtp 流时，backend/Analyzer 拉流会触发 WVP `on_stream_not_found` 自动 INVITE，不必先手动点播。停模拟器（SIGTERM）后 WVP 应马上离线，再点同步，业务列表 `is_online=0`。

```bash
  -c:v libx264 -preset veryfast -tune zerolatency -an \
  -f flv rtmp://127.0.0.1:9995/live/test1 \
  > /tmp/ffmpeg_push.log 2>&1 &
```

## 7. 常见坑

| 现象 | 处理 |
| --- | --- |
| 网页 502 | 后端没起：重跑 `start_easysva.ps1` |
| 同步出国标一堆「登录中」 | 旧逻辑把 ZLM 半程口、SSRC hex 也建成设备；已过滤。只认 **demo-ipc**。刷新列表即可 |
| `18080` 打开空白/404 | 跑过 `serve_wvp_ui.sh`；强制刷新 |
| 同学打不开网页 | 见 **§1.1**：关 Clash/VPN；用 `http://<本机IP>:8080/`（不要 `:80`）；管理员跑 `setup_windows_lan_access.ps1` |
| WVP 点播黑屏 / 超时 | 模拟器是否还在跑；设备是否在线；stream 是 `设备ID_通道ID`；Clash 时用 `127.0.0.1` 不要用局域网 IP |
| Chrome 打开 `.live.flv` 没画面 | 正常，用业务页 / WVP「播放」或 VLC |
| 预览冻第一帧 / 只有一帧不动 | 已修：去掉 live `loop`、flv stall 自愈。请 **Ctrl+Shift+R**。模拟器约每分钟可能闪几秒属已知现象，真机无此限制；B/C 黑屏 / DHCP 见 [国标功能使用说明书.md](./国标功能使用说明书.md) §9 |
| WSL 里 ZLM 报 Stamp expired / 时钟乱跳 | `systemctl disable --now systemd-timesyncd`（让 WSL 跟宿主机时钟，不要再开 guest NTP） |
