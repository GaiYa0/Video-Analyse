## 2. 架构一句话（约 40 秒，可对着白板/PPT）

> 国标拆两段：  
> **WVP** 管信令——SIP 注册、保活、目录、点播 INVITE，管理页在 18080。  
> **ZLM** 管媒体——收国标 PS/RTP，转成网页能看的 FLV，以及 Analyzer 拉的 RTSP。  
> 业务系统只同步「已经在 WVP 里注册成功的通道」，再拿播放地址给前端和 Analyzer。  
> 所以：**在线看 SIP；有没有画面看有没有点播出流。**

可顺嘴对比：

| | 直连摄像头 | 国标 |
| --- | --- | --- |
| 取流 | `live/<设备id>` | `rtp/<设备_通道>` |
| 检测 | 同一套 Analyzer | 同一套 Analyzer |

## 3. 现场演示（主戏，约 4–6 分钟）

### 3.1 WVP：证明是真注册

打开 `http://127.0.0.1:18080/`（`admin` / `SvaDemo@2026`）→ 国标设备。

> 这是平台侧。设备编码 `34020000001320000001` 显示在线，说明模拟器已经做完 REGISTER，不是我们在数据库里手写一条假在线。没有注册的话，后面点播一定黑屏。

### 3.2 业务：同步 + 列表

打开 `http://localhost:8080/` → 设备管理 → **同步国标设备** → 找到 **demo-ipc**（`camgbf0b09a04`）。

> 业务库演示只保留这一条国标设备。同步会过滤测试脏数据，避免列表里冒出一堆半截设备。  
> 这里的在线状态跟 WVP 的 SIP 走，不跟「此刻 ZLM 里有没有画面」绑死。

### 3.3 预览：有画面

点 **预览视频**。

> 画面走 Nginx 的 `/rtp/`，和直连的 `/live/` 一样反代，浏览器不直连 ZLM 的 9992。  
> 进度条经常是 `0:00 / 0:00`，直播流没有片长，这是正常的。

（可选）若老师要确认媒体层：本机 VLC 打开  
`http://127.0.0.1:9992/rtp/34020000001320000001_34020000001320000001.live.flv`

### 3.4 离线（建议做，约 1 分钟）

另开一个 WSL 窗口：

```bash
pkill -f gb28181_sim.py || true
```

再回业务页点一次同步。

> 模拟器正常退出会发注销（Expires=0），同步后应变离线。  
> 这说明在线不是「曾经推过流就一直绿」，而是跟注册生命周期走。

演示完离线若还要继续讲布控，再重新跑一遍 `start_gb_sim.sh`。

### 3.5 分析器取流（有时间再做；没有就口头）

布控：选 **demo-ipc** + 原 YOLO（水杯演示目标用 **cup**）+ 闭合区域 + 录像引擎 **算法服务器** → 启动。

> 发给 Analyzer 的地址必须是 `rtsp://127.0.0.1:9994/rtp/…`，不能是 `live/camgb…`。  
> 国标没有流时，backend 会后台 warm 点播，ZLM 的 `on_stream_not_found` 也会自动 INVITE；Analyzer 拉流超时大约 25 秒，就是在等这场点播。  
> 检测模型没换，换的只是输入 URL。

睡岗用国标源：

> 睡岗算法在验收点 2 已过。国标源上的睡岗/YOLO 细联调是同学 B 和阶段四联调范围；阶段三主交付是注册、同步、预览和取流复用。

## 4. 阶段三踩过的坑（约 2–3 分钟，老师问「遇到什么问题」就讲这段）

开场可先说一句：

> 国标这条链路问题大多出在「信令以为通了、媒体其实没通」，或者「本机通了、同学那边黑屏」。我们按现象排过几轮，主要这几类。

### 4.1 库里「在线」、点播却黑屏

| | |
| --- | --- |
| **现象** | 设备列表绿/在线，预览一直黑 |
| **原因** | 早期用 seed 脚本只改数据库，**没有真 SIP REGISTER**；WVP 点播找不到真实 Contact |
| **解决** | 废弃「假在线」；上 `gb28181_sim.py` 真注册/保活/目录；业务只同步 WVP **已注册**通道 |

口述：

> 我们踩过假在线：库里写在线没有用，点播一定黑。后来改成模拟器真 REGISTER，同步也只收已注册通道。

### 4.2 同步出一堆脏设备

| | |
| --- | --- |
| **现象** | 点一次同步，列表冒出 SSRC 十六进制名、`设备_通道` 重复行、半程测试机 |
| **原因** | 把测试残留和通道派生名都当新设备入库 |
| **解决** | 同步过滤脏数据；演示库只保留一条国标 **demo-ipc** |

口述：

> 同步规则收紧了，避免验收现场列表很乱；演示只留 demo-ipc 一条。

### 4.3 已注册，但 Analyzer / 预览仍拉不到流

| | |
| --- | --- |
| **现象** | WVP 在线，布控报 pull stream 失败，或预览要干等很久 |
| **原因** | 国标要先 INVITE 才有 `rtp` 流；HTTP 若同步等点播会被堵死；Analyzer 超时太短 |
| **解决** | 预览/布控后台 **warmRtp**；ZLM **on_stream_not_found** 自动 INVITE；Analyzer **stimeout ≈ 25s**；play 前先 stop，避免和 WVP 播放器抢同一路 |

口述：

> 在线不等于有画面。我们把点播做成后台预热和自动 INVITE，分析器多等一会儿，这样预览和布控都不会卡死在 HTTP 上。

### 4.4 Analyzer 误拉 `live/camgb…`，国标出不了框

| | |
| --- | --- |
| **现象** | 国标设备布控启动失败，或日志里 streamUrl 仍是 live |
| **原因** | 国标行若按直连逻辑拼 URL，会走到不存在的 `live/<apeId>` |
| **解决** | `device_type=gb28181` 时从 `play_url` 解析 `/rtp/<设备_通道>`，下发 `rtsp://127.0.0.1:9994/rtp/...`；停止监控**不清空**国标 `play_url` |

口述：

> 检测没换，换的是取流公式。国标必须拉 rtp，不能拉 live。

### 4.5 预览「永久冻帧 / 只有一帧」

| | |
| --- | --- |
| **现象** | 有过第一帧之后画面卡住，像静态图 |
| **原因（叠加）** | ① SIP Via 带 `\r`、对 100 Trying 误加 To-tag → WVP 异常；② 前端 live `<video loop>` + flv.js 缓冲配错；③ 模拟器 RTP 用墙钟 `time.time()`，时钟一跳时间戳乱；④ WSL 开了 `systemd-timesyncd` 和宿主机抢时钟回拨 |
| **解决** | 修 SIP Via / To-tag 解析；去掉 live `loop`，修正 flv.js 配置并加 **stall 自愈**；模拟器改用**单调时钟**；WSL **关掉** guest NTP，跟宿主机时钟；`start_wvp.sh` 设 `media.stream-ip=127.0.0.1` 减少本机播放被代理干扰 |

口述：

> 冻帧不是单一 bug，是信令、播放器、RTP 时间戳、WSL 时钟几层叠在一起。一层层剥开后，主路径可以稳定预览；若还像旧画面，浏览器强刷一下。

### 4.6 本机有画，同学 B/C 黑屏；或 DHCP 换 IP 后挂掉

| | |
| --- | --- |
| **现象** | A 本机正常，别人电脑预览黑；或换了 Wi‑Fi IP 后注册/点播失败 |
| **原因** | `play_url` 仍是 `127.0.0.1`；WVP `sdp_ip` 还是旧局域网地址；Clash 拦局域网；有人直连 ZLM `:9992` |
| **解决** | 预览统一走 Nginx **`/rtp/`**（`:8080`）；给同学跑 `rewrite_play_url_for_lan.sh <LAN>`；`start_wvp.sh` 校正过期 `sdp_ip`；**`zlm_server.host` 保持 127.0.0.1** 给 Analyzer；A 本机 Clash 下只用 localhost |

口述：

> 本机预览和给同学看要分开处理：同学改 play_url 成局域网，分析器仍然拉本机 127.0.0.1，不能混。

### 4.7 竖屏片源、模拟器偶发闪断（已知）

| | |
| --- | --- |
| **现象** | 竖屏视频难解/画面怪；水杯模拟器约每分钟闪几秒 |
| **原因** | 片源竖屏；模拟器长推码流边界问题（真机一般无） |
| **解决** | 推流前 **pad 成 1280×720**；前端 watchdog / 重新 INVITE 自愈。验收主功能不受影响，真机接入后无此限制 |

口述：

> 闪断是模拟器已知现象，会自己恢复；我们没把它当成主路径失败。真机不受这个限制。

### 4.8 一句话收束（可接老师追问）

> 阶段三最大的收获是把「注册 / 点播 / 预览 / 分析取流」边界划清，并且把假在线、冻帧、局域网预览这些坑写成了手册，避免下次再踩。

## 6. 老师常问 · 短答（背这几句）

**Q：为什么要 WVP，ZLM 自己不能国标吗？**  
A：演示机把信令和媒体拆开：WVP 做 SIP，ZLM 做收流和转封装。业务只对接「已注册通道」，不自己实现国标信令栈。

**Q：在线但黑屏？**  
A：在线只说明注册成功。画面还要 INVITE 出 RTP。预览/布控会触发点播；先看 WVP 是否在线、模拟器是否在推、ZLM 里有没有 `app=rtp` 那条流。

**Q：和阶段一的 RTSP 预览有何不同？**  
A：前端都是 FLV 预览，路径从 `/live/` 换成 `/rtp/`；分析器从拉 `live` 换成拉 `rtp`。YOLO/睡岗逻辑复用。

**Q：模拟器算不算数？**  
A：走的是真国标信令与媒体格式（REGISTER、INVITE、PS/RTP）。用来验收平台接入闭环；真机只是换一端设备，协议路径相同。

**Q：开发中最难的是什么？**  
A：预览永久冻帧——信令解析、播放器 loop/缓冲、RTP 时间戳和 WSL 时钟叠在一起，要分层排查（见上文 §4.5）。其次是分清「在线」和「有画面」。

**Q：预览为什么偶发卡一下？**  
A：水杯模拟器长推时大约每分钟可能闪几秒，前端会自愈重连。真机 IPC 一般没有这个问题，不影响注册/同步/离线主功能。

**Q：`zlm_server.host` 为什么必须是 127.0.0.1？**  
A：Analyzer 和 ZLM 都在演示机本机，必须拉本机 RTSP。给同学看预览时，只改库里的 `play_url` 成局域网地址，不要改 Analyzer 用的 host。

**Q：分工？**  
A：我（A）演示机、WVP/模拟器、同步、预览与国标文档；B 分析器与算法；C 前端与合稿。今天我侧重国标接入演示。

**Q：阶段三还差什么？**  
A：若验收要求真机画面，需要接真实 IPC（先停模拟器，避免编码冲突）。国标源上睡岗细调、交付 PPT/视频属阶段四。模拟器主路径和截图已经齐。

## 7. 现场翻车急救（小声看，别念）

| 现象 | 先做 |
| --- | --- |
| 业务 502 / 登不上 | 重跑 `start_easysva.ps1`；Clash 改用 localhost |
| WVP 设备离线 | 看 `start_gb_sim.sh` 是否在跑；SIP 是否绑当前电脑局域网 IP（DHCP 变了重跑 `start_wvp.sh`） |
| 同步不到设备 | WVP 先在线；再点同步；不要用 seed 脚本假写在线 |
| 预览黑屏 | 模拟器在推；业务预览走 `/rtp/`；Ctrl+Shift+R；不要和 WVP 播放器同时猛点同一路 |
| 布控 pull stream 失败 | 确认 `streamUrl` 是 `rtp/…`；等十几秒点播；WVP 的 `on_play` 要通（WVP 得在） |
| 需要给 B/C 看 | `bash scripts/rewrite_play_url_for_lan.sh <当前LAN>`，对方用 `http://<LAN>:8080/` |

| 入口 | 账号 |
| --- | --- |

| WVP `127.0.0.1:18080` | `admin` / `SvaDemo@2026` |
