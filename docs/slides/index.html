P2 · 先定义清楚：什么算睡岗 09
不报 · 正常工作

短暂低头、头在动、
正脸看屏幕

原系统的 sleep 只看「框不动」，会把这些全报出来——它不是姿态意义上的睡岗。

  • 低头看键盘、翻资料，几秒又抬头
  • 看手机、写字，头一直在动
  • 人走开、被遮挡、背景路人
要报 · 睡岗

趴桌、长时间低头不动

我们判的是姿态 + 时间，两个都满足才报。正拍、侧拍都要能用。

  • 头部俯仰角持续 ≥ 32°（看不见髋 38°）
  • 连续低头分三档：2 s 疑似 · 5 s 确认 · 15 s 严重，只升不降
  • 头基本不动，低头时间占比 ≥ 80%

P2 · 怎么算「低头多少度」 10

姿态几何 · YOLO11n-Pose · 17 关键点

三个点，一把尺子，
一个角

  • 三个点：头点（鼻 / 眼 / 耳中点）、颈点（双肩中点）、躯干方向（髋 → 肩）
  • 尺子 = max(0.42 × 躯干长, 0.5 × 肩宽)，正拍、侧拍共用
  • 俯仰角 = 头相对颈的抬升 ÷ 尺子 → 坐直 ≈ 0°，头落到颈点 ≈ 90°
  • 直立门控：正脸且头在颈上方 → 角度封顶 18°，「看屏幕」永远不报

● 头点 · ○ 颈点 · 躯干方向 髋→肩 · 无髋时用肩线转 90°

P2 · 多帧时序与防误报 11

时长分档 + 五道证据门

低头够久
只是必要条件

低头 ≥ 32° 进入、抬头 < 22° 恢复（滞回防抖）；时长只决定档位（2 s / 5 s / 15 s），报不报还要五道门全过。

  • 低头占空比 ≥ 80% —— 挡住打字、翻资料的反复出入
  • 峰值到过 45°、头点位移 ≤ 0.45 尺 —— 挡住看手机、写字
  • 有效帧 ≥ 3、丢帧 ≤ 50% —— 挡住遮挡、走开、低帧率凑时长
  • 告警走原入口，类型 SLEEP_ON_DUTY，叠加时长、俯仰角、档位

在线 ≠ 有画面：从注册到出画五步
① 注册
IPC → WVP：REGISTER（Digest）/ 保活 / Catalog
此时设备列表显示「在线」—— 但还没有任何画面。
② 同步
后端「同步国标设备」读 WVP 已注册通道
写设备表 device_type = gb28181、play_url = /rtp/…；先探活 ZLM，过滤脏数据。
③ 点播
预览 / 布控请求 rtp/… → ZLM 无流 → WVP 发 INVITE
hook on_stream_not_found 后台自动触发，不堵页面；Analyzer 拉流超时 25 s 就是留给点播的窗口。
④ 出画
IPC 推 PS/RTP 进 ZLM → 网页 WS-FLV、Analyzer RTSP 同时可用
无人观看约 60 s 自动关流，再看即重新点播。
⑤ 离线
REGISTER Expires = 0 → 再同步 → is_online = 0
在线状态跟随 SIP 注册生命周期，不靠脚本假写。

常见追问 · 三个词分开 22

谁在编码、谁在转封装、谁在解码？

01
编码 · 一次
模拟器 ffmpeg 把测试片压成 H.264 再打进 PS；真机则是摄像头自己编码。预览前唯一一次编码。
→
02
转封装 · ZLM
解复用：拆 PS，把同一份 H.264 装进 FLV 或 RTSP。不重编码 —— 所以不是「转码」，视频编码仍是 H.264。
→
03
解码成画面 · 两端
Analyzer（FFmpeg 解码 → 检测）和浏览器 flv.js（预览）各自解码；ZLM 从不解成像素。

顺带三句要分开说：注册成功 ≠ 业务页有设备（还没同步）；有设备 ≠ 有画面（还没点播）；WVP 网页能播 ≠ 业务页能播（两条播放器不是一条路）。
