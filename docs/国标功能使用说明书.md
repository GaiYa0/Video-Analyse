## 1. 这条链路是什么

国标 **不是** ZLM 自己监听 SIP 5060。演示机把国标拆成两段，再接到业务系统：

| 段 | 组件 | 干什么 |
| --- | --- | --- |
| 信令 | **WVP**（开源 `wvp-GB28181-pro`） | SIP 注册 / 保活 / 目录 / 点播 INVITE；管理页 `:18080` |
| 媒体 | **ZLM**（MediaServer） | 收国标 **PS over RTP**，转成 HTTP-FLV / WS-FLV / RTSP |
| 业务 | **easySVA**（backend + web） | 「同步国标设备」→ 设备表；预览 / 布控只认已同步设备 |
| 推理 | **Analyzer** | 不实现 SIP；只拉 ZLM 上的 `rtsp://…/rtp/<设备_通道>` |

业务网页（easySVA `:8080`）**不会**自己做国标注册。它只同步 WVP 里**已注册**的通道，再把 `play_url` 给前端预览、给 Analyzer 拼拉流地址。

不要用 `seed_wvp_device.sh` 在库里假写「在线」——没有 REGISTER，点播一定黑屏。

当前演示设备：

| 项 | 值 |
| --- | --- |
| 业务名 | **demo-ipc** |
| `ape_id` | `camgbf0b09a04` |
| `device_type` | `gb28181` |
| 国标编码（设备 = 通道） | `34020000001320000001` |
| ZLM 流 | `app=rtp`，`stream=34020000001320000001_34020000001320000001` |

## 2. 国标如何与 ZLM 结合（架构）

### 2.1 总图

```text
┌─────────────┐  SIP REGISTER / Keepalive / Catalog
│ 国标 IPC    │ ─────────────────────────────────────► ┌──────────────┐
│ 或模拟器    │ ◄───────────────────────────────────── │     WVP      │
│ gb28181_sim │  INVITE / ACK / BYE（点播信令）          │  :18080 Web  │
└──────┬──────┘                                         │  :5060 SIP   │
       │                                                └──────┬───────┘
       │ MPEG-PS / RTP（媒体，UDP 常落在 30000–35000）            │
       │                                                       │ HTTP Hook
       ▼                                                       │（见下表）
┌─────────────┐  RTSP / HTTP-FLV / WS-FLV                 ▼
│    ZLM      │ ◄──────── Nginx /rtp/ ──────── easySVA 前端预览
│ :9992/:9994 │ ◄──────── rtsp://127.0.0.1:9994/rtp/… ── Analyzer
└─────────────┘
       ▲
       │ REST：openRtpServer / getMediaList / …
       └──────── WVP 点播时在 ZLM 开收流口，并把流名绑成 设备_通道
```

要点：

1. **WVP 不管像素**，只做国标信令，并指挥 ZLM「开一个 RTP 收流口」。  
2. **ZLM 不管 SIP**，只收 RTP、做转封装；`app=rtp` 与直连的 `app=live` 分开。  
3. **easySVA / Analyzer 不直连 SIP**，只消费 ZLM 上已经存在（或即将点播出）的流。

### 2.2 为什么要 WVP + ZLM，而不是「只要 ZLM」

| 能力 | WVP | ZLM |
| --- | --- | --- |
| GB28181 REGISTER / 目录 / 保活 | ✅ | ❌ |
| 点播 INVITE、会话 BYE | ✅ | ❌ |
| 收 PS/RTP、转 FLV/RTSP | 调 ZLM | ✅ |
| 给浏览器播、给 Analyzer 拉 | 经 ZLM URL | ✅ |

课件要求「推理链路复用」：睡岗 / YOLO 仍走 Analyzer；国标只换 **输入 URL**（`live/…` → `rtp/…`）。

### 2.3 ZLM Hook：WVP 怎么挂上 ZLM

`start_wvp.sh` 会把 ZLM（`/opt/SVA/mediaServer/config.ini`）的 hook 指到本机 WVP，例如：

| Hook | URL（示意） | 作用 |
| --- | --- | --- |
| `on_play` | `http://127.0.0.1:18080/index/hook/on_play` | 有人播流时鉴权 / 放行（WVP 未起时 RTSP 可能 401） |
| `on_stream_not_found` | `…/on_stream_not_found` | 要播的 `rtp/设备_通道` 还不存在 → **自动发起点播 INVITE** |
| `on_stream_none_reader` | `…/on_stream_none_reader` | 长时间无人看 → 可关流（现网约 **60s**） |
| `on_stream_changed` | `…/on_stream_changed` | 流注册 / 注销通知 WVP |
| `on_publish` | 常指向 WVP 或清空 | 推流鉴权；本机摄像头 RTMP 若被 401，可临时清空（国标 RTP 点播不依赖它） |
| `on_server_keepalive` 等 | `…` | 保活、录像回调等 |

因此：**先起 ZLM，再起 WVP 写 hook**；只起 ZLM 不起 WVP 时，业务去拉 `rtp/…` 可能失败或一直转圈。

### 2.4 媒体进 ZLM 之后长什么样

点播成功后，ZLM `getMediaList` 里应出现：

- `app` = **`rtp`**（不是 `live`）  
- `stream` = **`{设备国标编码}_{通道国标编码}`**（演示机两者相同：`34020000001320000001_34020000001320000001`）  
- `originTypeStr` 多为 **`rtp_push`**  
- 视频轨一般为 **H.264**

对外播放 / 拉流（本机）：

| 用途 | 地址形态 |
| --- | --- |
| 业务预览（经 Nginx） | `ws://127.0.0.1:8080/rtp/<stream>.live.flv` |
| VLC / 排障 | `http://127.0.0.1:9992/rtp/<stream>.live.flv` |
| Analyzer | `rtsp://127.0.0.1:9994/rtp/<stream>` |

直连摄像头走 **`/live/<apeId>`**；国标走 **`/rtp/<设备_通道>`**。Nginx 对两者都做了反代，浏览器不要直连 `:9992` 做业务预览。

## 3. 国标功能如何实现（端到端）

按时间顺序，一次完整闭环是这样的：

### 3.1 注册（有设备、无画面）

1. IPC / 模拟器向 **WVP SIP（局域网 IP:5060）** 发 `REGISTER`（Digest，密码 `12345678`）。  
2. WVP 记设备在线；Contact 指向设备侧（模拟器常见 `:15060`）。  
3. 平台拉 **Catalog / 目录**，得到通道。  
4. 此时列表「在线」≠ 已有画面——**还没点播，ZLM 里可以没有 `rtp` 流**。

### 3.2 点播（出画面）

1. 人或脚本触发点播：WVP 管理页「播放」、`start_gb_sim.sh` 末尾自动 play、业务预览 / 布控的 **warmRtp**、或 ZLM **`on_stream_not_found`**。  
2. WVP 调 ZLM 开 RTP 收流口（端口多在 **30000–35000**），并准备好流 ID `设备_通道`。  
3. WVP 向设备发 **INVITE**；设备 **200 OK + SDP**，再 **ACK**。  
4. 设备把画面以 **MPEG-2 PS over RTP** 推到 ZLM 收流口（演示机模拟器用 ffmpeg `-f vob`）。  
5. ZLM 解出 H.264，挂到 `rtp/设备_通道`，同时提供 FLV / RTSP。  
6. 前端 Jessibuca / flv.js 拉 WS-FLV；或 Analyzer 拉 RTSP。

### 3.3 同步进业务库

1. 业务页点「**同步国标设备**」（或脚本调同步 API）。  
2. backend 问 WVP「当前已注册通道」，过滤脏数据（SSRC hex、半程测试名、`gbcam001` 等）。  
3. 写入 / 更新设备行：`device_type=gb28181`、`gb_device_id`、`play_url`（含 `/rtp/<stream>.live.flv`）等。  
4. 演示库策略：业务侧只保留清晰的一条国标 **demo-ipc**。

`is_online` 跟 **WVP SIP 注册状态**，不跟「ZLM 此刻有没有 rtp」。流还在但已注销，同步后也应离线。

### 3.4 预览与布控（业务 / Analyzer）

| 动作 | 实现要点 |
| --- | --- |
| 前端预览 | 读设备 `play_url`；本机经 Nginx `/rtp/`；给 B/C 前跑 `rewrite_play_url_for_lan.sh <LAN>` |
| 布控启动 | backend 若发现国标，拼 Analyzer 的 `streamUrl=rtsp://127.0.0.1:9994/rtp/…`（从 `play_url` 解析 stream；解析不到则用 `gb_device_id` 规则） |
| 尚无 rtp 流 | backend **warmRtp** 后台点播；ZLM 无流时 **on_stream_not_found** 再 INVITE；Analyzer `stimeout` 约 **25s** 等待 |
| 停止布控 | **不清空**国标 `play_url`（避免下次又丢地址） |

直连设备对比：Analyzer 拉 `rtsp://127.0.0.1:9994/live/<apeId>`，检测逻辑相同。

### 3.5 离线

1. 模拟器正常退出（SIGTERM / `pkill`）发 `REGISTER Expires=0`。  
2. WVP 设备变离线。  
3. 业务再同步 → `is_online=0`。  
4. 不要用 `kill -9` 硬杀模拟器，否则可能来不及注销，列表还会绿一会儿。

### 3.6 和「直连 RTSP/RTMP」差在哪

| | 直连 | 国标 |
| --- | --- | --- |
| 谁推到 ZLM | 摄像头 / ffmpeg 推 `live/<id>` | 先 SIP 点播，再 RTP 进 `rtp/<设备_通道>` |
| 业务 `play_url` | `/live/…` | `/rtp/…` |
| Analyzer | `…/live/<apeId>` | `…/rtp/<设备_通道>` |
| 在线含义 | 常跟监控/推流 | **跟 SIP 注册** |

## 5. 同学 A：每天怎么开

**推荐一键（业务前后端 + WVP + 水杯模拟器）：**

```powershell
cd E:\video-analysis\Video-Analyse-main
.\scripts\start_demo.ps1 -WithGbSim
```

只要业务 + WVP、暂不推水杯：

```powershell
.\scripts\start_demo.ps1
```

分步等价：

```powershell
cd E:\video-analysis\Video-Analyse-main
.\scripts\start_easysva.ps1
wsl -d Ubuntu-22.04 -u root -- bash /mnt/e/video-analysis/Video-Analyse-main/scripts/start_wvp.sh
wsl -d Ubuntu-22.04 -u root -- bash /mnt/e/video-analysis/Video-Analyse-main/scripts/start_gb_sim.sh
```

| 顺序 | 脚本 | 作用 |
| --- | --- | --- |
| 1 | `start_easysva.ps1` | MariaDB / Redis / Nginx / backend / ZLM / Analyzer |
| 2 | `start_wvp.sh` | WVP Web + SIP；LAN 写入 SIP；ZLM hook → WVP |
| 3 | `start_gb_sim.sh` | 模拟 IPC：REGISTER → 目录 → 自动点播 → RTP 推画面 |

模拟器进程要保持运行。关栈：

```powershell
wsl -d Ubuntu-22.04 -u root -- bash /mnt/e/video-analysis/Video-Analyse-main/scripts/stop_all.sh
```

`stop_all.sh` 停 backend / 模拟器 / WVP / Analyzer / ZLM，**不停** MariaDB / Redis / Nginx。

给 B/C 看国标预览前（DHCP 变了再跑）：

```bash
bash scripts/rewrite_play_url_for_lan.sh <当前LAN>
```

Analyzer 只解析 `play_url` 里的 `/rtp/<stream>`，`zlm_server.host` **必须保持** `127.0.0.1`，不要改成局域网 IP。

## 6. 无真机：用水杯 / 自备视频

`start_gb_sim.sh` / `start_demo.ps1 -WithGbSim` 默认推 `docs/fixtures/monisleep.mp4`（国标睡岗演示）。换片源（WSL 里）：

```bash
VIDEO=/mnt/e/video-analysis/Video-Analyse-main/docs/fixtures/大树视频测试.mp4 \
  bash /mnt/e/video-analysis/Video-Analyse-main/scripts/start_gb_sim.sh
```

竖屏片源会 **pad 成 1280×720** 再推，避免 Analyzer 按横屏去解。想先转成横屏 H.264 再推：

```bash
bash scripts/prepare_gb_video.sh /path/to/in.mp4 /tmp/gb-ready.mp4
VIDEO=/tmp/gb-ready.mp4 bash scripts/start_gb_sim.sh
```

模拟器改过代码或片源后，必须 **重新跑一遍** `start_gb_sim.sh`，正在跑的旧进程不会自动换逻辑。

真机和模拟器不要同时用同一个国标编码。只停模拟器：

```bash
pkill -f gb28181_sim.py || true
```

正常退出（SIGTERM）会发 `REGISTER Expires=0`，WVP 应马上离线。

## 7. 怎么看画面

直播 FLV 进度条显示 `0:00 / 0:00` 是正常的（没有片长）。竖屏树/人若「几乎不动」，先看是不是片源本身动作小，再查 RTP 是否还在推。

### 7.1 业务页（给答辩 / B / C 看这条）

1. 打开 `http://localhost:8080/`（A）或 `http://<LAN>:8080/`（B/C）
2. 登录 `admin` / `admin123`
3. **设备管理** 找到 **demo-ipc**
4. 点 **同步国标设备**（模拟器脚本末尾已经调过一次，也可再点）
5. 点 **预览视频**

本机预览走 Nginx：`ws://127.0.0.1:8080/rtp/<stream>.live.flv`，不要直连 ZLM `:9992`。B/C 必须先让 A 跑过 `rewrite_play_url_for_lan.sh`，否则弹窗里还是 `127.0.0.1`，别人电脑黑屏。监控墙走 `/live/`，国标走 `/rtp/`。

### 7.2 WVP 管理页（A 排障用）

1. `http://127.0.0.1:18080/` → `admin` / `SvaDemo@2026`
2. **设备接入 → 国标设备**
3. 设备 `34020000001320000001` 应为 **在线**
4. **通道 → 播放**（建议选 **Jessibuca**）

`start_gb_sim.sh` / `start_demo.ps1 -WithGbSim` 结束时已经自动点播过；再点「播放」等于再拉一次。WVP 点播和业务预览会互踩同一条 rtp 流：业务侧会先 stop 再 play。不要两边同时猛点。

无人观看约 60s 后流可能被关；再点播放应重新 INVITE。一直转圈时先看模拟器是否在推、ZLM `getMediaList` 是否还有 `app=rtp`。

WVP `:18080` **不对局域网开放**，B/C 不用开。

### 7.3 VLC（确认媒体层）

```text
http://127.0.0.1:9992/rtp/34020000001320000001_34020000001320000001.live.flv
```

Chrome 往往不能直接播 HTTP-FLV。本机网页请用 §7.1。

## 8. 同步、在线、离线

「同步国标设备」只收 WVP **已注册**通道，不会把半程测试名、8 位十六进制 SSRC、旧的 `gbcam001` 建成新设备。业务库演示只留 **demo-ipc** 这一条国标。

`is_online` 跟 **WVP SIP 注册状态**，不跟「ZLM 里还有没有 rtp」。流还在、设备已注销，列表也应显示离线。

停模拟器后：WVP 设备离线 → 再点同步 → 业务列表 `is_online=0`。

## 9. 布控（YOLO / 睡岗）

国标设备布控与直连一样：设备管理 → 布控 → 选算法 → 启动。

差别只在取流：

| 设备类型 | Analyzer 实际去拉 |
| --- | --- |
| 国标 `gb28181` | `rtsp://zlm:9994/rtp/<设备ID_通道ID>` |
| 直连 RTSP / RTMP | `live/<ape_id>` |

ZLM 还没有这条 rtp 时，预览 / 布控会后台 `warmRtp`（触发 WVP `on_stream_not_found` 自动 INVITE），**不会**把 HTTP 卡住十几秒。Analyzer 拉流超时约 25 秒。停止监控 **不会**清空国标 `play_url`。

改过 `server/Analyzer` 后，在演示机重编并替换运行中的二进制：

```bash
bash scripts/rebuild_analyzer.sh
```

睡岗判定、YOLO 类别、告警页展示归同学 B / C，本说明书不改那些逻辑。

## 10. 接入真正的国标 IPC

1. 停模拟器（见 §6），不要和真机抢同一个 20 位编码。
2. 已起 `start_demo.ps1` 或 `start_easysva.ps1` + `start_wvp.sh`。Clash 尽量关。
3. Windows 防火墙放行 **UDP/TCP 5060**，以及 **UDP 30000–35000**（RTP）。
4. 摄像机与演示机同一网段，能 ping 通 **当前**局域网 IP（`ipconfig` 的 WLAN IPv4；DHCP 变了要改 WVP `sip.ip` 和摄像机里的 SIP 服务器地址）。
5. 摄像机「国标 / GB28181」填写：

| 摄像机项 | 填这个 |
| --- | --- |
| SIP 服务器地址 | 演示机当前局域网 IP（**不要** `127.0.0.1`） |
| SIP 端口 | `5060` |
| SIP 服务器 ID / 平台 ID | `34020000002000000001` |
| SIP 域 | `3402000000` |
| 设备国标编码 | 机身 20 位编码（**不要**再用模拟器的 `34020000001320000001`） |
| 注册密码 | `12345678` |
| 心跳 | 建议 ≤ 60 秒 |

6. 等几十秒。WVP → 国标设备：新编码 **在线** → 通道 → 播放，应是现场画面。
7. 注册成功但点播黑屏：该设备传输模式改成 **UDP**（不要 TCP-PASSIVE），再播。
8. 业务页「同步国标设备」，出现该通道后再预览 / 布控。不必先在 WVP 里手动点播。

## 11. 常见问题

| 现象 | 先查什么 |
| --- | --- |
| 业务页 502 / 打不开 | Clash 开着却用了局域网 `:80`。改 `http://localhost:8080/` |
| 设备列表在线，预览第一帧冻住 | 模拟器进程是否还在；ZLM `getMediaList` 是否还有 `app=rtp`。需重新 `start_gb_sim.sh` / 再点播放 |
| 预览黑屏、WVP 显示在线 | 有没有真 REGISTER（不是 seed）；模拟器是否往 **当前** LAN:5060 注册；`sdp_ip` 是否过期（`start_wvp.sh` 会改） |
| WVP / ZLM 一直转圈 | 常因无人观看 60s 关流，或点播「已有请求在途」。等几秒再点播放；看模拟器日志是否还在 `vob RTP pkts=…` |
| B/C 黑屏，A 本机正常 | 没跑 `rewrite_play_url_for_lan.sh <LAN>`；或 B/C 开了 Clash；或打开了 `:80` 而不是 `:8080` |
| 「已有请求在途」 | 上一次预览/点播还没结束。等几秒，不要连点。业务侧会先 stop 再 play |
| 布控失败 / Analyzer 拉不到流 | 模拟器或真机是否在线；等 warmRtp + 25s；确认 `play_url` 含 `/rtp/<设备_通道>`；WVP 必须在（`on_play`） |
| DHCP 换 IP 后注册失败 | 摄像机 / 模拟器仍指向旧 IP。重跑 `start_wvp.sh`；真机改摄像机里的 SIP 服务器地址 |
| 无人观看一段时间后没流 | `streamNoneReaderDelayMS=60000`。再预览会重新 INVITE |
| 列表仍显示在线，模拟器已关 | 是否 `kill -9` 没发注销。用 `pkill` / `stop_all.sh`；再点同步 |
